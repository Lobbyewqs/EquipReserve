## 实测结果

`python -m unittest -v test_platform`：**12 项通过，11.579 秒**。

| 场景 | 结果 |
| --- | --- |
| 100 个用户竞争同设备同槽，100 个工作线程 | 1 个成功、99 个 SLOT_OCCUPIED；预约与占用各 1 条 |
| 同用户同键 20 个并发请求 | 同一预约 ID；改变内容复用键返回冲突 |
| 创建占用后注入异常 | 预约、占用、成功幂等记录、成功审计均回滚；同键可重试成功 |
| 取消旧预约后重新预约，再次取消旧预约 | 新占用保留 |
| 时段开始时取消与领取竞争 | 取消被拒绝，领取成功，实物指针一致 |
| 截止时刻领取与过期竞争 | 领取失败，状态 EXPIRED，实物未借出 |
| 截止后重建 Store 并补扫 | 1 次过期；重复扫描 0 次变化 |
| 前笔逾期、后笔领取、归还旧笔后再领取 | 先阻止，归还后可领；旧归还重试不清空新借用 |
| 设备停用 | 禁止新预约和领取；允许归还；占用保留 |
| 权限与所有权 | 他人预约取消 404；普通用户借还 403 |
| 时间边界 | 28 个时段；开始前不可领、截止前一秒可领；14 日范围外拒绝 |
| 真实 HTTP | 首页 200、未登录 401、CSRF 403、预约 201、重放 ID 一致、管理员接口 403、登出后 401 |

100 请求竞争这一轮耗时 5.441 秒。此数字包含本机 SQLite 写串行化和审计写入，属于正确性测试记录，不是吞吐量基准，也不代表 MySQL 性能。

Python 编译与 JavaScript 语法检查通过。本地首页返回 200，浏览器中实际打开并检查了登录页。登录后的设备、预约、管理界面尚未逐项进行浏览器点击验证；没有声称前端全流程已通过。

## 环境问题与修复

最初测试使用系统临时目录，被受管 Windows 权限阻止打开 SQLite 文件；改用项目内隔离的 data/tests 临时目录。第一次 HTTP 测试被沙箱回环网络策略阻止，随后在允许本机连接的执行环境下完整重跑，12 项全部通过。没有关闭系统安全功能。

## 未验证

- MySQL 行锁、死锁重试、生产负载及跨进程长时间压测。
- 强制终止进程/掉电恢复。当前重启补扫测试重建数据库连接与 Store，未模拟操作系统崩溃。
- 登录后浏览器点击流程、移动端截图、不同浏览器兼容性。
- HTTPS、生产部署与另一台机器的复现。
